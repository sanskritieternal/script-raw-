## Editorial scope

**Focus / example question:** How does a user need become a shipped change?

**Coverage:** Trace requirement, design, code, test, deployment, and feedback.

**Evidence to seek:** project requirements and design records, versioned artifacts, test and deployment data, incident reports, and user research

**Limits:** Name system, team context, time period, and metric definition. Do not infer causality from a single project or a passing test suite.

Before Phase 1, narrow this guidance to a specific case, source or work, and the relevant place, population, version or period. Record that choice in the episode's story question and research summary.
