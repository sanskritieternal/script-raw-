## Editorial scope

**Focus / example question:** How do goals, actions and feedback connect in one user interaction?

**Coverage:** Explain users, tasks, interfaces and feedback through one bounded interaction; distinguish visual preference from successful and accessible use.

**Evidence to seek:** Use primary definitions and a documented end-to-end example. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting.

**Limits:** Test with users; interface preference alone is not measured benefit. Niche boundary: Human interaction with interfaces and measured task performance; product shopping and software implementation have separate homes.

Before Phase 1, narrow this guidance to a specific case, source or work, and the relevant place, population, version or period. Record that choice in the episode's story question and research summary.
