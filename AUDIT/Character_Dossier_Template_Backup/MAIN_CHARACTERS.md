# Main characters

## Purpose and applicability

Record the central cast for this episode. A historical person, animal or fictional entity can be central. Main/supporting describes narrative importance; protagonist/opponent/ally describes story function. If there is no cast, record an episode-specific Not applicable reason in both this document and the manifest.

## Character profiles

Create one authoritative profile per character with a unique ID such as CHAR_001. Include name, aliases, narrative role, background, goals, motivation, obstacles, strengths, weaknesses, personality and emotional arc. Record introduction, relevant scenes and relationships by character ID. Never duplicate a profile in SUPPORTING_CHARACTERS.md; move it and update references if importance changes.

## Appearance and voice

Describe distinguishing features, body proportions, expressions and gestures. Specify speaking style, pronunciation, vocal qualities, pacing and emotional range; link the voiceover guide for delivery. Reference appearance-lock entries, costume IDs and planned reference asset IDs. Distinguish requested design from approved references and actual generated media.

## Evidence and depiction

Label each historical assertion with its Phase 1 claim/source locator, and each invented backstory, dialogue or visual detail as creative interpretation or fiction. Record uncertainty, depiction limits and relevant permissions without claiming clearance. Personality and private emotions are not verified merely because a real person is depicted.

## Scene and reference links

Map profiles to scene numbers when available; until then mark the mapping pending. Use relative links to actual episode files. Supporting records: [overview](CHARACTER_WORLD_GUIDE.md), [supporting cast](SUPPORTING_CHARACTERS.md), [appearance lock](CHARACTER_APPEARANCE_LOCK.md), [relationships](RELATIONSHIPS_TIMELINE.md), [voice](05_Voiceover_Guide.md).

## Full individual profile worksheet

Repeat an expanded subsection for each actual main character. Supply the answers, not a list saying they should be supplied. Use this structure as relevant:

1. **Identity:** stable ID, full name/aliases, profile ownership, narrative importance and story function.
2. **Source/design boundary:** named evidence for action/background; explicitly creative features; unresolved context.
3. **Narrative task:** goal in this episode, obstacle, decision, consequence and change across actual scene regions.
4. **Observable personality:** gestures and responses that show it; distinguish sourced speech/action from invented private psychology.
5. **Physical proposal:** face silhouette, eye/brow/nose/hair or nonhuman traits, proportions, posture, scale and distinctive features relevant to the design.
6. **Wardrobe and possessions:** authoritative costume/prop IDs, ownership transitions and variant ranges.
7. **Expression/movement sheet:** individual expressions, ordinary gestures, range limits and representative scene uses.
8. **Voice:** narrator versus performed dialogue, language/pronunciation, tone, reference rights and actual recording status.
9. **Scene progression:** introduction, turning point, closing role and active appearance variant.
10. **Generation handoff:** reusable identity wording, reference-sheet views/IDs, actual-versus-planned assets, exclusions and review criteria.

The profile must let a reference artist or scene writer make the intended version without supplying the missing decisions themselves. Mention-only figures belong in supporting records; do not inflate the cast to achieve a length target.

## Required editorial depth

Before filling this document, read the shared source `CORE/PIPELINE/03_Phase2_PRODUCTION_BIBLE/PRODUCTION_DETAIL_STANDARD.md`. Write actual episode decisions, individual entries, representative scene use, examples, exceptions and acceptance checks relevant to this file. Do not submit a short summary or a list of instructions as completed production content. Keep genuinely inapplicable fields explicitly justified; do not invent factual detail, assets or approvals to increase length. Structural validation alone does not verify editorial depth.
