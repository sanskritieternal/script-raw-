## Bounded case

Compare the `gpt2` and `cl100k_base` encodings assigned to GPT-2 and GPT-4 in OpenAI's pinned `tiktoken` revision `4e71bbe0c078468e00fefbf94b39849389f346e5`. Use identical strings in both encodings, including `Hello, world!`, `नमस्ते दुनिया` and `東京へ行く`. Record the literal Unicode code points and whether normalization is applied. Model names here describe the pinned library mapping; the episode must not imply these are current hosted products or current billing rules.

## Reproduced sample counts

The [measurement script](../../../Scripts/archive/topic_bank/001_184/measure_tokenizer_case_001.py) used literal text, no normalization, and checked that each token-byte sequence and decode round-tripped to the input. Its JSON records code points, input hashes, token IDs, token bytes, interpreter and platform.

| Fixed input | `gpt2` tokens | `cl100k_base` tokens |
|---|---:|---:|
| `Hello, world!` | 4 | 4 |
| `नमस्ते दुनिया` | 23 | 13 |
| `東京へ行く` | 9 | 7 |
| `café` (composed) | 3 | 2 |
| `cafe` plus combining acute accent | 4 | 3 |

These are results for the exact inputs and library version only. They do not measure model quality, comprehension, pricing or current hosted behavior.

## Controlled factor check

The [factor script](../../../Scripts/archive/topic_bank/001_184/analyze_tokenizer_factors_001.py) crosses each pinned encoding's pre-tokenization pattern with each pinned merge-rank set. Its [saved output](BANK-001-013_FACTORIAL.json) records the chunks, token counts, input hashes and round-trip checks. The two mixed combinations are analytical constructs, **not** encodings assigned to actual models.

| Fixed input | GPT-2 pattern + ranks | GPT-2 pattern + `cl100k_base` ranks | `cl100k_base` pattern + GPT-2 ranks | `cl100k_base` pattern + ranks |
|---|---:|---:|---:|---:|
| `Hello, world!` | 4 | 4 | 4 | 4 |
| `नमस्ते दुनिया` | 23 | 14 | 23 | 13 |
| `東京へ行く` | 9 | 7 | 9 | 7 |
| `café` (composed input) | 3 | 2 | 3 | 2 |
| `cafe` plus combining acute accent | 4 | 3 | 4 | 3 |

For the Japanese and accent inputs, the two patterns produce the same chunks; switching the rank set changes the count in this check. For the Hindi input, switching ranks under the GPT-2 pattern changes 23 to 14; with `cl100k_base` ranks, switching the pattern changes 14 to 13. The Hindi patterns split the input into different chunks, so both components matter to that comparison. These observations concern only these strings, this implementation and this version. The English input is a useful counterexample to any claim that one encoding always uses fewer tokens.

The composed-accent and combining-accent inputs are deliberately separate byte and code-point sequences, as recorded in the [measurement](BANK-001-013_MEASUREMENT.json). The script applies no normalization. Their different counts should not be used as evidence about visual appearance, meaning or model comprehension.
