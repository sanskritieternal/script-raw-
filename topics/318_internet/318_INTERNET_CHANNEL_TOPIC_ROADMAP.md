## 1. Channel Progression Strategy

This curriculum organizes the core disciplines of Internet across four progressive tiers:
- **Tier 1: Internet Foundations & Core Mechanisms (Beginner / Scratch)** — Core physical and conceptual fundamentals, terminology, primary mechanisms, and foundational observation methods in Internet.
- **Tier 2: Internet Methodological Deep Dives & Empirical Evidence (Intermediate)** — Detailed instrumentation, measurement metrics, classification systems, and documented case studies of Internet.
- **Tier 3: Internet Advanced Systemic Paradigms & Comparative Dynamics (Upper Intermediate)** — Complex systemic interactions, historical shifts, anomalous patterns, and comparative analyses across different contexts in Internet.
- **Tier 4: Internet Frontier Technologies, Global Impact & Future Horizons (Advanced / Masterclass)** — Emerging technological breakthroughs, policy frameworks, environmental and human impact, and long-term evolutionary projections for Internet.

## 3. Topic Catalog (Scratch to Advanced Curriculum)

### Tier 1: Foundational Frameworks
1. **The Architecture of Internet: How Networks Interconnected**
   - *Question:* Which protocol and governance decisions enabled one interconnection?
   - *Key Focus:* Use dated RFCs, network maps, and operator records. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
2. **Internet: A Famous Internet Failure**
   - *Question:* What did a documented outage reveal about dependencies?
   - *Key Focus:* Trace routing, DNS, power, applications, and user effects. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
3. **Internet: People Running the Internet**
   - *Question:* Who maintains cables, exchange points, routing, and support?
   - *Key Focus:* Credit operators and local technicians. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
4. **Internet: A Request Across Networks**
   - *Question:* How does a device reach a named service?
   - *Key Focus:* Map address, DNS, routing, transport, and server. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
5. **Internet: The End-to-End Trade-off**
   - *Question:* Where should reliability or security functions live?
   - *Key Focus:* Compare protocol design, network controls, and application needs. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
### Tier 2: Methodological Deep Dives
6. **Internet: A Route That Disappeared**
   - *Question:* Which public measurements explain a reachability incident?
   - *Key Focus:* Check BGP, DNS, traceroute, and blind spots. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
7. **Internet: A New Protocol Deployed**
   - *Question:* Did one protocol improve a defined user outcome?
   - *Key Focus:* Measure adoption, latency, compatibility, and failure. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
8. **Internet: A Standards Decision**
   - *Question:* How did one working group resolve a design dispute?
   - *Key Focus:* Read proposals, minutes, RFCs, and implementation evidence. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
9. **Internet: An Internet Outage Timeline**
   - *Question:* What failed first and which users were affected?
   - *Key Focus:* Use dated operator reports and independent measurements. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
10. **Internet: Autonomous Networks Together**
   - *Question:* How do networks exchange routes and traffic?
   - *Key Focus:* Trace one bounded path and peering arrangements. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
### Tier 3: Advanced Analytical Paradigms
11. **Internet: Connectivity Over Time**
   - *Question:* What explains a measured access change?
   - *Key Focus:* Separate subscription, usable quality, affordability, and coverage. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
12. **Internet: One Service Across Protocol Eras**
   - *Question:* How did speed, security, and reach change?
   - *Key Focus:* Compare matched tasks and dated implementation. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
13. **Internet: Conditional Network Evolution**
   - *Question:* What assumptions shape a proposed change?
   - *Key Focus:* State interoperability, incentives, security, and deployment cost. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
14. **Internet: The Internet Is the Web?**
   - *Question:* Which services share IP but differ above it?
   - *Key Focus:* Trace a concrete web and non-web task. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
15. **Internet: One Packet's Approximate Journey**
   - *Question:* What can public measurements really show?
   - *Key Focus:* Name vantage points and avoid implying exact path certainty. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
### Tier 4: Frontier Systems & Interdisciplinary Paradigms
16. **Internet: Where the Internet Service Ends**
   - *Question:* Which device, ISP, DNS, cloud, and app controls matter?
   - *Key Focus:* Draw a named service boundary. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
17. **Internet: A Domain Lookup to Response**
   - *Question:* What inputs and outputs occur at each layer?
   - *Key Focus:* Use a safe trace and mask personal data. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
18. **Internet: Centralized Service on Distributed Networks**
   - *Question:* What improves and what fails when a service concentrates?
   - *Key Focus:* Compare latency, availability, control, and cost. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
19. **Internet: A DNS or Routing Error**
   - *Question:* How did a bounded error affect users?
   - *Key Focus:* Use public postmortem and measurements, not exploit steps. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
20. **Internet: What a Speed Test Misses**
   - *Question:* Does one measurement reflect real experience?
   - *Key Focus:* Check endpoint, time, congestion, packet loss, and application. Evidence base: dated RFCs and standards discussions, operator postmortems, public routing and DNS measurements, network maps, and consented user and worker accounts.
