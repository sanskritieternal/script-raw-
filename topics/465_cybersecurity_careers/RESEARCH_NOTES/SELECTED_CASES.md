# Selected cybersecurity-career case: NICE role vocabulary

## BANK-465-043 — role statements versus employment evidence

- [NIST SP 800-181 revision 1](https://csrc.nist.gov/pubs/sp/800/181/r1/final) defines the NICE Framework structure for describing cybersecurity work. NIST's [current-version page](https://www.nist.gov/itl/applied-cybersecurity/nice/nice-framework-resource-center/nice-framework-current-versions) lists separate Work Role, Task, Knowledge and Skill components; it labeled component version 2.2.0 (28 April 2025) when inspected. The framework structure and components have different version histories.
- These are NIST's authored classifications, not observations of what every employer hires for or proof that a course or certificate yields a role. A work role is not identical to a job title, headcount, vacancy, salary or authorized security activity. Component IDs and statements may change, so exact examples need a pinned download/version.
- Script gate: pin the framework component version, inspect a particular role's task and skill mapping, then compare dated employer postings or interviews before claims about hiring or career entry. Avoid operational intrusion advice.
- Semantic boundary: BANK-465-030 contrasts defensive and authorized testing roles in general; this case explains how a named versioned role taxonomy is assembled and misread. Cybersecurity bank 326 owns actual incidents and controls, not hiring promises.
