## 1. Channel Progression Strategy

This curriculum organizes the core disciplines of Human-Computer Interaction across four progressive tiers:
- **Tier 1: Human-Computer Interaction Foundations & Core Mechanisms (Beginner / Scratch)** — Core physical and conceptual fundamentals, terminology, primary mechanisms, and foundational observation methods in Human-Computer Interaction.
- **Tier 2: Human-Computer Interaction Methodological Deep Dives & Empirical Evidence (Intermediate)** — Detailed instrumentation, measurement metrics, classification systems, and documented case studies of Human-Computer Interaction.
- **Tier 3: Human-Computer Interaction Advanced Systemic Paradigms & Comparative Dynamics (Upper Intermediate)** — Complex systemic interactions, historical shifts, anomalous patterns, and comparative analyses across different contexts in Human-Computer Interaction.
- **Tier 4: Human-Computer Interaction Frontier Technologies, Global Impact & Future Horizons (Advanced / Masterclass)** — Emerging technological breakthroughs, policy frameworks, environmental and human impact, and long-term evolutionary projections for Human-Computer Interaction.

## 3. Topic Catalog (Scratch to Advanced Curriculum)

### Tier 1: Foundational Frameworks
1. **The Architecture of Human-Computer Interaction: How Human-Computer Interaction Developed**
   - *Question:* Which user task led to an interaction technique's development?
   - *Key Focus:* Trace one interaction technique from its original user task through design and evaluation; distinguish prototype influence from widespread adoption. Evidence base: Trace dated origin records and subsequent interpretations. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting..
2. **Human-Computer Interaction: A Documented Human-Computer Interaction Case**
   - *Question:* What does a celebrated interface's evaluation establish about its users and tasks?
   - *Key Focus:* Examine one documented interface using user population, task, environment and measured outcomes; assess whether its success transfers to other contexts. Evidence base: Read the original evaluation and its population, comparator, outcomes and limitations. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting..
3. **Human-Computer Interaction: People behind Human-Computer Interaction**
   - *Question:* Whose accessibility or support work shaped an interface project?
   - *Key Focus:* Document overlooked participants, accessibility specialists or support workers in one interface project; use consented accounts and credit their contributions. Evidence base: Use attributable contribution records and consented participant accounts. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting..
4. **Human-Computer Interaction: Understanding Human-Computer Interaction**
   - *Question:* How do goals, actions and feedback connect in one user interaction?
   - *Key Focus:* Explain users, tasks, interfaces and feedback through one bounded interaction; distinguish visual preference from successful and accessible use. Evidence base: Use primary definitions and a documented end-to-end example. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting..
5. **Human-Computer Interaction: Tradeoffs in Human-Computer Interaction**
   - *Question:* How do research methods change the usability conclusion for one task?
   - *Key Focus:* Compare usability-study methods for one interaction question; examine participant selection, task realism, learning effects and measurement uncertainty. Evidence base: Compare original methods, assumptions, measures and uncertainty. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting..
### Tier 2: Methodological Deep Dives
6. **Human-Computer Interaction: An Open Human-Computer Interaction Question**
   - *Question:* Why did real-world use differ from a usability test's prediction?
   - *Key Focus:* Investigate a mismatch between a usability test and real-world behavior; compare context, incentives, training and excluded user groups. Evidence base: Compare competing explanations and specify missing discriminating evidence. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting..
7. **Human-Computer Interaction: A Tool for Human-Computer Interaction**
   - *Question:* Does an interaction technology improve tasks for the users it claims to serve?
   - *Key Focus:* Evaluate one interaction technology on defined tasks with appropriate users; compare errors, accessibility, workload and fallback options. Evidence base: Compare validation, deployment and follow-up against a stated baseline. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting..
8. **Human-Computer Interaction: Decisions in Human-Computer Interaction**
   - *Question:* How did research evidence influence a documented design decision?
   - *Key Focus:* Reconstruct one design decision using research findings, constraints and stakeholder authority; distinguish user consultation from decision-making power. Evidence base: Use decision records, assigned authority and attributed accounts. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting..
9. **Human-Computer Interaction: A Turning Point in Human-Computer Interaction**
   - *Question:* What changed in task completion after a dated interface redesign?
   - *Key Focus:* Examine a dated interface redesign or policy change through its effect on task completion and access; use comparable observation periods. Evidence base: Build a dated before-and-after record without assuming causation. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting..
10. **Human-Computer Interaction: How Human-Computer Interaction Works**
   - *Question:* Where does a user encounter error, feedback and recovery in a task?
   - *Key Focus:* Map one user's task from goal through actions, feedback, error and recovery; identify system and organizational handoffs. Evidence base: Trace the process, custody transfers and assigned responsibilities. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting..
### Tier 3: Advanced Analytical Paradigms
11. **Human-Computer Interaction: When a Human-Computer Interaction Approach Faltered**
   - *Question:* Why did users adopt or abandon an interaction pattern?
   - *Key Focus:* Explain adoption or abandonment of one interaction pattern using observed use, support records and alternatives; avoid treating popularity as usability. Evidence base: Compare a dated series with competing explanations for change. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting..
12. **Human-Computer Interaction: across Two Periods**
   - *Question:* How do interface versions compare after accounting for familiarity and training?
   - *Key Focus:* Compare two interface versions on the same tasks and user conditions; account for familiarity, training and changes in underlying functionality. Evidence base: Align definitions, samples, versions and measurement conditions. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting..
13. **Human-Computer Interaction: Possible Next Steps in Human-Computer Interaction**
   - *Question:* What user evidence would a proposed interface need before deployment?
   - *Key Focus:* Assess a proposed interface through user research, accessibility, evaluation and maintenance requirements; separate demonstration from validated benefit. Evidence base: Read the actual proposal and distinguish required conditions from achieved results. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting..

   - *Key Focus:* Test one intuitive-design or frictionless-use claim against task evidence; examine user diversity, error rates and conditions excluded from the claim. Evidence base: Trace the public claim to original evidence and retain its qualifications. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records. Starting framework: W3C accessibility evaluation resources (https://www.w3.org/WAI/test-evaluate/). Select and verify the dated underlying case sources before scripting..

Evidence base: Build a dated evidence trail including dissent and unresolved findings. Case records: task protocols, participant criteria, usability observations, accessibility evidence and design records.
