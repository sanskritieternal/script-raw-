# PHASE 5 — FINAL AUDIT
## MASTER_Phase5_FinalAudit.md

**Purpose:** This is the final gate before a video is cleared for publishing. Phase 5 does not add new content or research; it only verifies that everything produced in Phases 0–4 is accurate, safe, complete, legal, and optimized for YouTube.

**Input:** The entire project folder for one topic, containing `01_Phase0_Configuration/CONFIG.md`, `02_Phase1_RESEARCH_BIBLE/`, `03_Phase2_PRODUCTION_BIBLE/`, `04_Phase3_SCENE_BREAKDOWN/`, and `05_Phase4_PRODUCTION_PACKAGE/`. Use `CORE/PIPELINE/CONTRACT.md` and schema 5.0 for current gates and paths.

**Output:** `Audit_Report.md` and, only if no blocking findings remain, `Completion_Certificate.md`. The certificate attests to the text production package review, not rendered assets or publication. Any FAIL item must be fixed before completion.

## AUDIT RULES

1. **One auditor, one checklist.** The auditor must be a different persona from the writer who produced Phase 3 and Phase 4 (or at least must re-check every item as if seeing it for the first time).
2. **Any FAIL = STOP.** If any single item receives a FAIL, the project cannot be marked complete. The auditor must record:
   - The failing item code (e.g., B5).
   - A short explanation of the issue.
   - The exact file/line where the issue occurs.
   - The required fix.
3. **Fix and re-audit.** After the fix, only the previously failed section and any directly related items need to be re-checked. All other sections remain valid.
4. **All applicable items PASS = text package complete.** Record `N/A` with a reason for inapplicable business, platform or rendered-asset checks. The auditor fills out the Completion Certificate only after blockers are resolved. A separate production and publishing review is needed for rendered assets.
5. **No new features in audit.** This phase does not allow "just one more scene" or "let me add a better source." If the issue is a real gap, fix it; if it is an enhancement, defer to a future version.

## MODE BEHAVIOR

### Interactive Mode (default)
When a user says "audit this topic," the agent:
1. Reads the topic's project folder.
2. Goes through the 70 checklist items one section at a time.
3. Reports the verdict for each section as it finishes.
4. Stops immediately on any FAIL and asks the user whether to fix it now or mark it as a deferred issue.

### Autonomous Mode
When `AUTONOMOUS=1` or the user says "run full audit automatically," the agent:
1. Completes all 70 checks without asking questions.
2. Uses conservative defaults: any item that cannot be verified is marked FAIL, not PASS.
3. Produces a final audit report with all fail items and a fix plan.
4. Does not publish or sign the certificate until the user confirms the fixes.

---

## REMINDERS FOR THE AUDITOR

- You are not the writer. Be skeptical.
- If a number feels too round or too dramatic, verify it.
- If a claim sounds like a rumor, downgrade it to "reported" or remove it.
- If the visuals are more sensational than the facts, the thumbnail is clickbait.
- If the script would embarrass a real person who did nothing wrong, it fails E4 and E10.
- Legal and financial risks are not negotiable; everything else can be fixed with time.
